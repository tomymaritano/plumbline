Plumbline

A plumb line tells you a wall is vertical. These skills tell your agent whether a design still is.

The check

  • Does this interface hide real complexity, or just pass things through?
  • Can this method be understood without reading another one in a different file?
  • Is error handling pushing work onto callers that the module could handle itself?

Install

Once per tool. Installing it in Claude Code does not install it in Cursor.

/plugin marketplace add tomymaritano/plumbline
/plugin install plumbline@plumbline-plugins
npx skills add tomymaritano/plumbline --skill '*'

On a host that installs the skills without the plugin namespace, drop the plumbline: prefix when you call one.

codex plugin marketplace add tomymaritano/plumbline
codex plugin add plumbline@plumbline

Needs Codex CLI 0.142.0 or newer. The app and the CLI share this install.

git clone https://github.com/tomymaritano/plumbline.git ~/.cursor/plugins/local/plumbline

Restart Cursor, then check the Customize panel.

grok plugin install tomymaritano/plumbline

Add --trust to skip the confirmation. /plugin lists what installed.

copilot plugin marketplace add tomymaritano/plumbline
copilot plugin install plumbline@plumbline-plugins

OpenCode, Antigravity, Factory Droid, Kimi, and Pi each have their own command. Every install is on GitHub.

Besides the checks

  • Call one by name. /plumbline:test-worth decides which tests to write or keep. /plumbline:fault-locality finds where a panic or a red test may be fixed. On a host without the plugin namespace, drop the plumbline: prefix.
  • When an agent opens a pull request after running these checks, the body ends with one Plumbline-Skills: line naming the skills whose checks actually ran.
  • Review on stop is off until you turn it on. In Claude Code, a turn that writes a lot of code can be asked to run red-flags before it finishes. Other agents get the same instruction in the project's AGENTS.md.
  • A review can write .plumbline/findings.md so the next one leads with what changed, and stops repeating a trade-off you already accepted.
  • The skills are Markdown. They send nothing anywhere. test-worth edits tests only after you say yes. fault-locality edits only on apply, and only the function that made the bad value or the missing path to a policy the module already has.
Run a design check on a pull request. It comments only when the change makes the design worse. ci-review
